# 평가 편향 점검과 재실행 결과

## 판단

기존 노트북의 지표 계산은 예측 점수와 정답으로 수행하며 결과를 1.0으로 덮어쓰는 코드를 확인하지 않는다. 입력 특징에서 정답·사기 플래그·거래 후 잔액을 제외한다. 다만 같은 Validation을 조기 종료·후보 선택·임계값 선택·성능 보고에 반복 사용하므로 선택 편향을 확인한다. 기존 1.0은 튜닝 데이터의 성능으로만 기록한다.

## 수정한 평가 절차

실행 `20261119T073653Z-1d0e70df`에서 기존 Train을 정답과 무관한 누적 거래 수 기준으로 시간순 분할한다. 동일 step은 양쪽으로 나누지 않는다.

| 용도 | step | 거래 수 | 사기 수 |
| --- | --- | ---: | ---: |
| 내부 학습 | 1–234 | 3,066,415 | 2,649 |
| 내부 튜닝 | 235–281 | 754,184 | 544 |
| 기존 Validation 고정 평가 | 282–354 | 1,248,498 | 762 |

내부 튜닝 구간에서 조기 종료·모델 선택·F1 최대 임계값 선택을 수행한다. Validation을 읽기 전에 `frozen_selection.json`에 모델 해시·특징 목록·임계값·선택 후보를 기록한다. 평가 시 저장 모델의 SHA-256을 대조하며 Validation 결과로 재선택하지 않는다. 모든 후보는 동일한 LightGBM 설정으로 학습한다. 모델을 전체 Train으로 재학습하지 않고 내부 학습 구간의 모델을 유지한다.

## 재실행 지표

| 후보 | Precision | Recall | F1 | PR-AUC | AP |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기준 특징 | 0.840678 | 0.650919 | 0.733728 | 0.750220 | 0.750157 |
| 잔액 특징 추가·내부 튜닝에서 선택 | 0.997382 | 1.000000 | 0.998689 | 0.999988 | 0.999976 |
| 송금자 잔액 전체 제거 | 0.091720 | 0.242782 | 0.133141 | 0.217967 | 0.184786 |

선택 모델의 고정 임계값은 `0.006350361245177384`로 기록한다. TP 762건, TN 1,247,734건, FP 2건, FN 0건을 확인한다. 낮은 자리수를 반올림하면 PR-AUC가 1.0으로 보일 수 있으므로 충분한 소수 자릿수로 표시한다.

송금자 잔액 전체 제거 실험은 거래 전 잔액·로그 잔액·잔액 대비 금액 비율·차액·전액 거래 여부·잔액 0 여부를 함께 제외한다. 큰 성능 하락으로 잔액 관련 특징에 대한 의존도를 확인한다. 이 실험만으로 잔액 특징이 부적절한 정답 누출이라고 단정하지 않는다. 실제 서비스 적용 시 거래 전 잔액의 가용 시점과 PaySim 외 데이터에서도 관계가 유지되는지 확인한다.

## 한계와 산출물

기존 Validation은 과거 특징 설계와 모델 비교에서 이미 관찰했으므로 이번 수정만으로 완전히 미관찰한 독립 데이터가 되지는 않는다고 명시한다. 최종 Test는 아직 읽지 않으며, 후속 평가에서 모델과 임계값을 고정한다. 수치를 의도적으로 낮추거나 높이기 위해 결과에 맞춰 평가 설정을 변경하지 않는다.

실행 노트북은 [05_bias_audit_temporal_validation.ipynb](../notebooks/05_bias_audit_temporal_validation.ipynb)를 사용한다. 모델과 고정 선택 정보는 `artifacts/models/20261119T073653Z-1d0e70df/`에 저장한다. 지표 CSV·PR 곡선·선택 모델의 Validation 예측은 `artifacts/reports/20261119T073653Z-1d0e70df/`에 저장한다. 생성 산출물은 Git에서 제외한다.
