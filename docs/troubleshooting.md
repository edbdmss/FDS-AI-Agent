# 트러블슈팅

## PySpark 이력 join에서 컬럼 이름이 중복되는 문제

### 증상

과거 거래 이력을 송신자·수신자 기준으로 원본 거래에 각각 join한 뒤 `step`을 참조할 때 Spark가 컬럼이 모호하다는 오류를 발생시킨다. 이력 테이블과 원본 거래에 `account_id`, `step`이 같은 이름으로 남아 join 이후 컬럼 참조를 구분할 수 없다. 첫 수정 뒤에는 join 조건에서 아직 기존 `account_id` 이름을 참조해 `UNRESOLVED_COLUMN` 오류가 발생한다.

### 원인

송신자와 수신자 이력은 모두 계좌 ID와 step을 키로 갖는다. 이 키들을 역할별 이름으로 바꾸더라도 join 조건과 결과 정리 코드가 이전 이름을 사용하면 컬럼 해석 오류가 계속 발생한다. Spark DataFrame은 join 후 중복 이름을 자동으로 하나로 합치지 않는다.

### 해결

송신자 이력 키를 `_send_account_id`, `_send_step`으로, 수신자 이력 키를 `_receive_account_id`, `_receive_step`으로 명시적으로 바꾼다. 각 join 조건도 변경된 키 이름과 원본 거래의 `nameOrig` 또는 `nameDest`, `step`을 비교하도록 맞춘다. join이 끝나면 역할별 보조 키를 drop해 후속 컬럼 참조가 모호해지지 않도록 한다.

### 검증

수정한 노트북 전체를 다시 실행해 6,362,620건의 특징 데이터를 생성한다. 분할별 행 수와 사기 건수를 입력 manifest와 대조하고, Parquet을 다시 읽은 집계 요약이 일치하는지 확인한다. 실행은 `verified: true`로 완료하며 executor task 134건이 완료되고 실패 task는 0건임을 확인한다. 노트북의 모든 셀이 오류 없이 끝나고 Ruff 검사와 `git diff --check`도 통과한다.

### 재발 방지

같은 테이블을 여러 역할로 join할 때 키를 join 전에 역할별 이름으로 바꾸고 join 조건도 새 이름을 사용하도록 작성한다. join 바로 다음에는 보조 키를 제거하고 필요한 컬럼 이름이 유일한지 확인한다.
