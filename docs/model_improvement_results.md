# LightGBM 고도화 결과

기존 1.0 수치는 모델·임계값 선택에 반복 사용한 Validation 결과로 기록한다. 평가 편향을 수정한 재실행은 [05_bias_audit_temporal_validation.ipynb](../notebooks/05_bias_audit_temporal_validation.ipynb)에서 수행한다. 이 문서의 수치를 독립적인 최종 성능으로 사용하지 않는다.

실행 `20261119T072837Z-fd2f6a7d`에서 기존 Spark 특징 Parquet을 재사용하고 거래 전 잔액 기반 특징 7개를 추가한다. 전체 Train으로 학습하고 동일 Validation에서 F1 최대 임계값을 선택한다.

| 후보 | Precision | Recall | F1 | PR-AUC | 최적 iteration |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기준 모델 | 0.794793 | 0.681102 | 0.733569 | 0.758815 | 444 |
| 잔액 특징 추가 | 1.0 | 1.0 | 1.0 | 1.0 | 2 |
| 트리 세분화 | 1.0 | 1.0 | 1.0 | 1.0 | 4 |
| 사기 가중치 10 | 1.0 | 1.0 | 1.0 | 1.0 | 2 |

동률 후보 중 먼저 평가한 잔액 특징 추가 모델을 선택한다. 임계값 0.020475286031760687에서 TP 762건, TN 1,247,736건, FP·FN 0건을 확인한다. 모델과 설정은 `artifacts/models/20261119T072837Z-fd2f6a7d/`에 저장하고 비교 CSV와 PR 곡선은 같은 실행 ID의 보고서 폴더에 저장한다.

## 완전 분리 결과 점검

정답, 거래 후 잔액, 규칙 기반 사기 플래그를 특징에서 제외한다. 가장 큰 gain을 갖는 특징은 `origin_balance_equals_amount`로 확인한다. 거래 전 잔액이 양수이고 거래 금액과 같으며 유형이 TRANSFER 또는 CASH_OUT인 단순 규칙을 추가 점검한다.

| 구간 | 규칙에 해당하는 사기 | 규칙에 해당하는 정상 | 규칙 밖 사기 |
| --- | ---: | ---: | ---: |
| Train | 3,123 | 0 | 70 |
| Validation | 755 | 0 | 7 |

위 결과로 PaySim의 합성 거래 패턴이 성능을 강하게 지배함을 확인한다. Validation 1.0은 실제 금융 거래에서의 완전 탐지를 보장하지 않는다. 반복 선택에 사용한 Validation 수치로 기록하고, Test 일반화 성능은 아직 확인하지 않은 상태로 구분한다. Test 평가에서는 모델과 임계값을 고정한다.

후속 추론에서는 [고도화 노트북](../notebooks/04_lightgbm_improvement.ipynb)의 `enrich` 계산과 manifest의 특징 순서·범주 목록을 동일하게 적용한다. 선택 임계값을 보정된 사기 확률로 해석하지 않는다.
