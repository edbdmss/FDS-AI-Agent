# 대화형 거래 조사 Agent

`notebooks/10_conversational_agent.ipynb`의 설정 셀을 실행한 뒤 마지막 입력 셀에서 대화한다. 입력창에 `의심 거래 1건 찾아줘`, `그 거래를 조사해줘`, `그 보고서를 다시 보여줘`를 차례로 입력한다. `종료`를 입력해 마친다. 중간 시연 셀은 실제 외부 호출과 조사 보고서 저장을 수행한다.

`POST /v1/chat`에 `message`와 `history`를 전달한다. 응답의 `answer`는 모델 답변, `status`는 처리 상태, `actions`는 실제 실행한 도구와 결과를 표시한다. 다음 요청의 history에 이전 user·assistant 메시지를 추가한다. 최근 12개 메시지만 허용하며 서버는 대화 이력을 영속 저장하지 않는다. 노트북은 이 이력을 자동 관리한다.

```json
{"message": "의심 거래 1건 찾아줘", "history": []}
```

LangGraph는 모델 판단 → 도구 실행 → 모델 재판단을 반복한다. Groq `openai/gpt-oss-120b`가 다음 도구 중 하나를 선택한다.

| 도구 | 동작 |
| --- | --- |
| search_transactions | 저장된 최신 거래를 최대 10건 검색한다. |
| get_prediction | 거래의 저장된 LightGBM 점수와 판단을 조회한다. |
| investigate_transaction | 기존 조사 그래프를 실행하고 새 보고서를 저장한다. |
| get_investigation | 저장된 보고서를 재조사 없이 조회한다. |

한 요청에서 최대 4회 도구를 실행한다. 호출 실패는 `provider_error`, 실행 한도 도달은 `limit_reached`로 반환한다. 모델 답변 완료는 `completed`로 표시하며 개별 도구 실패는 actions의 error도 확인한다. 이미 저장된 보고서는 후속 모델 호출 실패에도 유지되므로 actions에서 report_id를 확인한다. 조사 요청을 반복하면 새 보고서를 저장한다.

대화 입력과 최근 이력, 거래 ID·점수·임계값·판단·조사 근거·보고서 ID를 Groq에 전달한다. DB의 계좌 식별자와 원시 이력은 도구 출력에서 제외한다. 사용자가 직접 입력한 내용은 그대로 전달하므로 키와 비밀번호를 입력하지 않는다. 최종 대화 문장은 생성 결과이므로 actions와 저장 보고서의 근거를 함께 검토한다. 인용 검증을 수행하는 기존 조사 설명과 자유로운 대화 답변의 검증 범위를 구분한다.

현재 날짜별 검색, 신규 거래 입력에 대한 추론, 거래 삭제·수정·차단은 도구로 제공하지 않는다. 기존 학습 모델의 예측 결과를 활용하여 조사한다. 인증과 사용자별 권한을 구현하기 전까지 로컬 시연 범위로 사용한다.

[Groq 도구 호출 문서](https://console.groq.com/docs/tool-use/overview)에 따라 함수 정의와 도구 결과를 전달한다. API 서버를 사용하려면 프로젝트 루트에서 기존 서버를 재시작하고 `/docs`의 `/v1/chat`을 실행한다. 노트북의 TestClient는 별도 서버 실행 없이 같은 API를 호출한다.
